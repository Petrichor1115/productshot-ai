# T25 · 多轮对话式改图与上下文回溯

> 状态：⬜ Todo ｜ 优先级：P2 ｜ 阶段：v1.2 交互形态
> 依赖：T14、T17、T06 ｜ 来源：T17 遗留项（多轮改图）· T14 遗留项（上下文回溯重生成）
> 规格状态：v1.2 规划；PRD v2.1 未定义多轮交互

## 1. 目标

支持以自然语言对已生成结果做增量修改（"再亮一点"、"把背景换成木纹"），系统自动解析指代对象与修改意图，并保留每一轮的版本链，可回溯到任意中间结果。

## 2. 背景与范围

**问题**：当前每次生成都是独立的，用户想微调只能改参数重新生成一次完整套图。T14 存了消息流水但没用于上下文，T17 的意图路由只处理单轮。

**在范围内**
- 指代解析：识别"这张"、"上一张"、"第二张"等指代表达并绑定到具体 generation
- 增量修改指令 → 提示词增量，基于上一张的图与 prompt 继续生成
- 版本链：`parent_id` 指向被修改的那张，形成可回溯的树
- 结果区展示版本链与"回到上一版"
- 上下文窗口：只携带最近若干轮，避免 prompt 无限膨胀

**明确排除**
- 局部重绘 / 涂抹选区（inpainting）→ 需画布交互，悬空
- 图层拆分与元素级编辑 → 悬空
- 跨会话上下文 → 会话即上下文边界

## 3. 前置依赖

- T14（消息流水提供上下文）、T17（意图与编辑链路）、T06（生成服务）

## 4. 任务清单

- [ ] `generations` 加 `parent_id` 与 `revision` 两个字段
- [ ] 指代解析：规则优先（"上一张"/"第 N 张"/"这张"），规则无法判定时回退为"最近一张成功结果"
- [ ] 指令改写：把"再亮一点"改写成可执行的提示词增量，而非替换整条 prompt
- [ ] 上下文窗口：携带父图的 prompt + 最近 3 轮指令，超窗口只保留父 prompt
- [ ] 结果区版本链 UI：显示 v1/v2/v3，可点击切换与"回到上一版"
- [ ] 每轮修改写一条 messages 记录（assistant 侧含修改说明）
- [ ] 修改失败时保持父版本不变，不破坏已有结果

## 5. 关键实现

```js
// 版本链：每次改图都以父记录为基点追加新记录
const newId = insertGeneration({
  session_id, shot_type: parent.shot_type,
  parent_id: parent.id,
  revision: parent.revision + 1,
  prompt: buildIncrementalPrompt(parent.prompt, instruction)
});

// 增量提示词：保留原约束 + 追加修改项
const buildIncrementalPrompt = (base, inst) =>
  `${base}\n\n在此基础上调整：${inst}\n其余保持不变。`;
```

**关键设计**：修改结果一律**新增记录**而非覆盖父记录，这样"回到上一版"永远可行，也天然满足 T15 里悬而未决的"重生成记录策略"决策。

## 7. 验收标准（AC）

1. 输入"把背景换成木纹"后，新图背景变化而商品主体保持不变。
2. 指代"上一张"能正确绑定到最近一张成功结果，不误改其他类型。
3. 连续修改 3 轮后版本链为 v1 → v2 → v3，可回到任意版本。
4. "回到上一版"后继续修改，能正确从该版本再次派生。
5. 修改失败时原有结果不受影响，且错误信息可读。
6. 每轮修改在消息流水中有对应记录。
7. 上下文超长时不报错，且不会因 prompt 过长被模型拒绝。

## 9. 风险与决策

| 风险 | 应对 |
|------|------|
| 指代歧义导致改错图 | 解析后在前端显示"将修改：主图 v2"，给用户反悔机会 |
| 多轮累积导致 prompt 膨胀 | 上下文窗口限制为最近 3 轮 + 父 prompt |
| 增量修改可能漂移原风格 | 提示词显式写"其余保持不变"；必要时提供"重新开始"入口 |
