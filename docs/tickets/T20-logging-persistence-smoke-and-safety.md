## 1. 目标

补齐四项工程化短板：请求日志中间件、数据库增量持久化、冒烟测试脚本化、上传内容安全校验，把"能跑"提升到"可维护、可回归、可上线"。

## 2. 背景与范围

**问题**：v1.0 排障靠 console；`persist()` 每次写操作全量写盘；端到端冒烟是手工核对；上传只校验格式体积，不做内容安全。

**在范围内**
- 结构化请求日志（含 traceId、耗时、状态码）
- `persist()` 改为节流/增量，降低写盘开销
- `scripts/smoke-test.js` 自动化冒烟并纳入回归
- 上传图片内容安全校验（违规图片拒绝）

**明确排除**
- 接入第三方内容审核服务（需密钥与费用）→ 先做本地基础校验，接口预留
- APM / 链路追踪平台 → v1.2
- 单元测试全量覆盖 → 仅关键路径冒烟

## 5. 关键实现

```js
// 节流持久化：合并高频写盘，退出前兜底
let pending = false;
function persist() {
  if (pending) return;
  pending = true;
  setTimeout(() => { fs.writeFileSync(DB_FILE, Buffer.from(db.export())); pending = false; }, 500);
}
process.on('SIGINT', () => { flushNow(); process.exit(0); });

// 冒烟断言：非零退出码即可被 CI 捕获
assert(res.status === 200, '生成接口应返回 200');
assert(results.length === 3, '应生成 3 张套图');
```

**静默失败防护**：冒烟脚本对每步做断言，任一失败以非零码退出，避免"看起来跑完其实没验"。

## 7. 验收标准（AC）

1. 每个请求输出一条结构化日志，含 traceId 与耗时，可据此串联一次调用。
2. 错误日志单独文件，含堆栈。
3. 连续 20 次写操作只触发少量写盘，且进程退出后数据完整。
4. `npm run smoke` 能在干净环境一键跑通，失败时非零退出。
5. 损坏图片（截断文件）上传被拒，不进入生成链路。
6. 冒烟覆盖：注册 / 会话 / 上传 / 生成 / 管理端记录五段。

## 9. 风险与决策

| 决策 | 原因 |
|------|------|
| 节流而非去节流 | 全量写盘在数据量增长后明显拖慢；节流 500ms 足够安全 |
| 内容安全先本地实现 | 无第三方服务密钥；接口预留便于后续替换 |
| 冒烟而非全量单测 | 时限内优先覆盖主链路回归 |
