## 1. 目标

把三类套图从串行生成改为并行出图，并把结果以流式方式逐步返回前端，将用户可感知等待从"三张串行总耗时"压缩到"接近单张耗时"。

## 2. 背景与范围

**问题**：T06 采用 `for...of` 串行调用，实测三类全选总耗时 41–44s，接近 PRD §8"三张累计 ≤ 90s"上限的一半，且用户全程只能看 loading，无法确认进度。

**在范围内**
- 三类图并发调用（`Promise.allSettled`）
- 生成结果分批返回（SSE 或分块 JSON），前端逐张渲染
- 前端三态改为逐张实时更新
- 并发度上限控制，避免触发方舟限流

**明确排除**
- 生成任务队列与后台异步化（用户可离开页面）→ v1.2
- WebSocket 全双工 → 当前单向推送即可

## 5. 关键实现

```js
// 并发出图：allSettled 保证单张失败不影响其余
const tasks = shotTypes.map(st => generateOne(st).then(
  r  => ({ shotType: st, status: 'success', ...r }),
  e  => ({ shotType: st, status: 'failed', error_msg: e.message })
));
const results = await Promise.allSettled(tasks);

// 流式返回：每完成一张立即 flush
res.writeHead(200, { 'Content-Type': 'text/event-stream' });
for (const p of tasks) {
  const r = await p;
  res.write(`data: ${JSON.stringify(r)}\n\n`);   // 逐张推送
}
```

**注意**：并发后 `generations` 记录的写入顺序不再等于 `shot_types` 顺序，前端必须按 `shot_type` 匹配而非按数组下标。

## 7. 验收标准（AC）

1. 三类全选总耗时较串行版本下降 ≥ 40%（基线 41–44s）。
2. 第一张图在 15s 内出现在页面上，无需等全部完成。
3. 单张失败时其余两张仍正常返回并渲染。
4. 并发 5 次连续请求不触发方舟 429。
5. 进度展示准确，不出现"已完成 4/3"类错误。

## 9. 风险与决策

| 风险 | 应对 |
|------|------|
| 并发触发方舟限流（429） | 设 `MAX_CONCURRENCY=3` 上限；捕获 429 时退化为串行重试一次 |
| SSE 在部分代理下被缓冲 | 响应头加 `X-Accel-Buffering: no`；必要时降级为整体 JSON |
| 流式中途断连导致状态不一致 | 以数据库 `status` 为准，前端断连后按会话重新拉取 |
