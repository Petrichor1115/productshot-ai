# T29 · 数据看板可视化与报表导出

> 状态：⬜ Todo ｜ 优先级：P2 ｜ 阶段：v1.2 管理端
> 依赖：T09、T10、T20 ｜ 来源：T09 遗留项（无时间范围筛选与导出）
> 规格状态：v1.2 规划；PRD v2.1 §5 仅定义四项统计卡

## 1. 目标

把管理端数据看板从"四个静态数字"升级为可看趋势、可定位问题、可导出的数据视图，支撑运营决策与故障排查。

## 2. 背景与范围

**问题**：当前看板只有总数与今日数，看不出增长趋势、成功率变化与失败原因分布，也无法导出给业务方。出问题只能靠查库。

**在范围内**
- 时间范围筛选（今日 / 7 天 / 30 天 / 自定义）
- 趋势图：每日生成量、每日活跃用户、成功率
- 分布图：生图类型分布、风格分布、失败原因 TOP5
- 核心效率指标：平均出图耗时、失败率
- CSV 导出（趋势明细与生图记录明细）
- 关键指标异常时的可视化提示（如失败率突增）

**明确排除**
- 实时大屏与秒级刷新 → 无必要
- 第三方 BI 对接 → v1.3
- 自定义报表与指标配置 → v1.3
- 用户侧个人数据看板 → v1.3

## 3. 前置依赖

- T09（看板框架与统计接口）、T10（生图记录数据）、T20（日志，用于耗时与失败原因统计）

## 4. 任务清单

- [ ] `GET /api/admin/stats` 扩展 `from` / `to` 时间参数，所有统计按区间过滤
- [ ] 趋势数据：按天聚合生成量与活跃用户数，缺失日期补零
- [ ] 成功率与失败率：按 generations 状态聚合
- [ ] 失败原因 TOP5：按 `error_msg` 归类聚合（需先做错误归类规则）
- [ ] 平均出图耗时：建议落库 `duration_ms` 字段，不靠日志反推（见 §9）
- [ ] 图表渲染：轻量图表方案，不引入重型依赖
- [ ] CSV 导出：趋势与记录明细两种，中文需 BOM 防乱码
- [ ] 失败率异常阈值提示（如 > 20% 标红）

## 5. 关键实现

```sql
-- 按天聚合，缺失日期由应用层补零（SQLite 无 generate_series 需自行补齐）
SELECT date(created_at) AS d, COUNT(*) AS cnt,
       SUM(CASE WHEN status='success' THEN 1 ELSE 0 END) AS ok
FROM generations WHERE created_at BETWEEN ? AND ?
GROUP BY d ORDER BY d;
```

```js
// CSV 中文乱码防护：写 UTF-8 BOM
res.setHeader('Content-Type', 'text/csv; charset=utf-8');
res.write('\uFEFF');
```

**耗时统计口径**：`duration_ms` 应在生成完成时落库（T06/T11 改造），而不是从日志反推——日志会丢、会跨请求，口径不可靠。

## 7. 验收标准（AC）

1. 切换时间范围后，四项统计卡与全部图表同步刷新且数值与 SQL 直查一致。
2. 趋势图缺失日期补零，不出现断点跳变。
3. 成功率与失败率之和为 100%。
4. 失败原因 TOP5 归类合理，同类错误不重复计数。
5. 平均耗时与单次实际耗时偏差在可接受范围（±10%）。
6. 导出 CSV 用 Excel 打开中文不乱码，行数与筛选结果一致。
7. 大数据量（万级记录）下统计接口响应 < 2s。
8. 非管理员调用全部统计与导出接口返回 403。
