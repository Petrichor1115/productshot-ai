# T22 · 爆款复刻与商品换色开通

> 状态：⬜ Todo ｜ 优先级：P1 ｜ 阶段：v1.2 功能开通
> 依赖：T17、T03、T06 ｜ 来源：T17 遗留项 · PRD §4.2 四大暂不开通功能
> 规格状态：v1.2 规划；PRD v2.1 仅规定"点击提示即将上线"，未定义两功能的行为与参数

## 1. 目标

开通四大预留功能中的"爆款复刻"与"商品换色"，补齐参考图与颜色参数的数据承载，并让管理端能按新 `gen_type` 分别统计与筛选。

## 2. 背景与范围

**问题**：T17 开通了 AI 生图并铺好了意图路由范式，但爆款复刻与商品换色仍是 toast。两者共同点是都需要**额外的输入维度**（参考图 / 目标色），这是 v1.0 schema 没有承载的。

**在范围内**
- 爆款复刻：商品图 + 参考爆款图 → 参考其构图、布光、色调生成新图
- 商品换色：商品图 + 目标颜色 → 保持形态与材质仅替换颜色
- `gen_type` 扩展 `viral_remake` / `recolor`
- 参考图与目标色的落库（`gen_params` JSON 字段）
- 管理端生图记录增加对应标签与筛选

**明确排除**
- 风格裂变（一图多变体）→ T23
- 爆款参考图库 / 素材管理 → 需额外产品定义，悬空
- 多参考图融合 → 当前仅支持单张参考
- 颜色自动推荐 → 需商品类目知识，悬空

## 3. 前置依赖

- T03（模型客户端）、T06（生成与记录）、T17（意图路由范式）

## 4. 任务清单

## 5. 关键实现

```js
// 统一用 gen_params 承载差异化入参，避免再加列
const genParams = JSON.stringify({
  ref_image: refPath ?? null,     // 爆款复刻
  color: colorHex ?? null,        // 商品换色
  style
});

// 换色提示词要点：约束不变的部分比描述要变的部分更重要
const tpl = `将图中商品主体颜色改为 ${colorHex}，严格保持商品形态、材质、光影与背景不变，仅替换主体颜色`;
```

**schema 演进策略**：差异化参数一律进 `gen_params` JSON，不再为每个功能加列——v1.2 后续功能（T23 风格裂变等）可直接复用，避免表结构反复迁移。

## 7. 验收标准（AC）

1. 上传参考图后爆款复刻出图，构图/色调与参考图有明显相关性。
2. 选择颜色后换色出图，商品形态与材质保持不变，仅颜色变化。
3. 两种 `gen_type` 正确落库，`gen_params` 可完整还原输入。
4. 切换会话后参考图与目标色可回填。
5. 管理端生图记录显示对应标签，可按类型筛选且计数正确。
6. 参考图非图片格式 / 超大时被拒并提示。
7. 未上传参考图时爆款复刻按钮禁用并提示原因。

## 9. 风险与决策

| 风险 | 应对 |
|------|------|
| 换色可能改变材质或背景 | 提示词强调"保持"约束；人工抽检 10 组确认保形率 |
| 爆款复刻涉及他人作品版权 | 参考图仅限用户自有上传；服务条款需声明用户对输入内容负责 |
| 参考图理解失败 | 降级为直接用原图 + 风格关键词生成，并明确提示已降级 |
