# T23 · 风格裂变与批量套图

> 状态：⬜ Todo ｜ 优先级：P2 ｜ 阶段：v1.2 功能开通
> 依赖：T17、T22、T11 ｜ 来源：T17 遗留项 · T15 遗留项（跨会话批量打包）
> 规格状态：v1.2 规划；PRD v2.1 未定义批量与裂变行为

## 1. 目标

开通"风格裂变"（一张商品图一次产出多种风格），并提供跨会话/跨商品的批量套图能力，一次性覆盖多 SKU 的出图需求。

## 2. 背景与范围

**问题**：v1.0 一次只能对一套参数出一组图。真实电商场景常有两件事：同一商品想对比多种风格做 A/B 测试；上新季有几十个 SKU 需要批量出图。当前只能逐个重复操作。

**在范围内**
- 风格裂变：单图 + 多选风格 → 一次产出 N×M 张（N 种风格 × 勾选的类型）
- 批量套图：一次上传多个商品 → 按统一参数各自出套图
- 裂变结果的对比视图（同类型跨风格并排）
- 跨会话批量打包 ZIP（承接 T15 遗留）

**明确排除**
- 批量任务的排队优先级与配额 → T21 队列已覆盖，本 ticket 只做入队
- 批量结果的逐张微调 → 复用 T15 单张重生成
- Excel / CSV 导入 SKU 清单 → v1.3
- 自动选最优风格 → 需评分体系，悬空

## 3. 前置依赖

- T17（意图路由与 gen_type 扩展）、T22（gen_params 承载）、T11（并发出图）、T21（任务队列，批量场景必需）

## 4. 任务清单

- [ ] 风格多选 UI：从单选 pill 改为多选，至少支持 2–4 种

- [ ] 结果区对比视图：按 `shot_type` 分行、按 style 分列并排展示

- [ ] 批量提交：为每个商品建独立会话或直接建批量 job（需决策，见 §9）
- [ ] 跨会话 ZIP：按勾选的会话打包（复用 T15 的打包接口，扩展入参）
- [ ] 数量上限保护：单次裂变与批量的总张数上限，防误操作刷爆额度

## 5. 关键实现

```js
// 裂变：笛卡尔积拆子任务，全部入队而非直接调用
const combos = styles.flatMap(s => shotTypes.map(t => ({ style: s, shotType: t })));
const items = combos.map(c => insertJobItem({ jobId, ...c, status: 'queued' }));

// 总数上限：裂变张数 = 风格数 × 类型数，超上限直接拒绝
const total = styles.length * shotTypes.length;
if (total > MAX_VARIANTS) return res.status(400).json({ error: `单次最多 ${MAX_VARIANTS} 张` });
```

**额度校验前置**：裂变与批量都是"一次操作产生大量出图"，必须在入队前一次性校验额度是否覆盖全部张数，避免生成一半额度耗尽（联动 T19）。

## 7. 验收标准（AC）

1. 勾选 3 种风格 × 3 类图，产出 9 张，且每张风格与类型组合正确。
2. 对比视图按类型分行、风格分列，可直观比较。
3. 批量上传 5 个商品后，各自产出独立套图且互不串图。
4. 超过总张数上限时被拒并提示，不产生半成品。
5. 额度不足以覆盖全部张数时，提交前即拦截（联动 T19）。
6. 跨会话 ZIP 能正确打包勾选会话的全部成功图片。
7. 批量任务在任务中心（T21）可见整体进度。

## 9. 风险与决策

| 决策 | 原因 |
|------|------|
| 裂变走任务队列而非同步返回 | 张数多、耗时长，同步必然超时；依赖 T21 |
| 批量为每个商品建独立会话 vs 单会话多商品 | **待决策**：前者数据模型干净、便于单品重试；后者管理成本低。倾向前者 |
| 设置总张数上限 | 防误操作；上限值需按方舟限流与额度策略确定 |
