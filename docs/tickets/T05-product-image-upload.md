## 1. 目标

实现商品原图上传：支持单会话最多 9 张同一商品多角度图片，完成格式与体积校验、安全落盘，并返回可供后续生成使用的路径数组。

## 2. 背景与范围

**在范围内**
- `POST /api/upload`（multer 中间件）
- 格式白名单：JPG / PNG / WEBP
- 单张 ≤ 10MB，单次会话累计 ≤ 9 张
- 文件名随机化，防覆盖与路径穿越
- 返回 `{ path }` 供前端拼缩略图

**明确排除**
- 图片压缩 / 裁剪 / 旋转 → 悬空
- 拖拽排序、图片预览编辑 → 悬空
- 断点续传、秒传 → 超出本地演示场景

## 3. 前置依赖

- T01（uploads 静态挂载）、T02（身份鉴权）

## 4. 任务清单

- [x] 配置 multer `diskStorage`，目标目录 `uploads/`
- [x] 文件名生成：`up-{timestamp}-{random}.{ext}`
- [x] `fileFilter` 做 MIME + 扩展名双重白名单校验
- [x] `limits.fileSize = 10 * 1024 * 1024`
- [x] 上传接口要求登录，未登录返回 401
- [x] 统一错误文案："请上传 JPG / PNG / WEBP 格式的图片" / "图片大小不能超过 10MB"
- [x] 前端上传后回显缩略图并提供单张删除

## 5. 关键实现

```js
const storage = multer.diskStorage({
  destination: 'uploads/',
  filename: (req, file, cb) => {
    const ext = path.extname(file.originalname).toLowerCase();
    cb(null, `up-${Date.now()}-${crypto.randomBytes(4).toString('hex')}${ext}`);
  }
});
const upload = multer({ storage, limits: { fileSize: 10 * 1024 * 1024 }, fileFilter });
```

**9 张上限的落点**：不在 multer 层限制（multer 按次计数），而在业务层按会话已存图片数校验——因为用户可能分多次上传到同一会话。

## 7. 验收标准（AC）

1. 上传 JPG / PNG / WEBP 成功，返回可访问的路径。
2. 上传 GIF / PDF / EXE 被拒，返回格式错误提示。
3. 上传 > 10MB 图片被拒，返回体积错误提示。
4. 同一会话第 10 张被拒，提示已达上限 9 张。
5. 同名文件多次上传不互相覆盖。
6. `uploads/` 下文件可通过 `/uploads/xxx.png` 直接访问。

## 9. 风险与决策

| 决策 | 原因 |
|------|------|
| 原图不压缩直接落盘 | 保证送模型的画质；v1.0 本地场景磁盘无压力 |
| 随机文件名 | 防覆盖 + 防用户构造路径穿越 |
| MIME 与扩展名双校验 | 仅信 MIME 可被伪造，仅信扩展名可被绕过 |

## 10. 遗留 / 后续

- 上传后不做病毒扫描与内容安全审核 → 公网部署必须补。
- 未限制单用户总配额 → 多用户场景下需配额与清理策略。
