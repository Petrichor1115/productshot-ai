## 6. 关键取值对齐记录

| 项 | PRD 表述 | 实际实现 | 结论 |
|----|----------|----------|------|
| `shot_type` 卖点图 | `selling` | `selling_point` | **以 `schema.sql` 为准**，前端标签仍显示"卖点" |
| 数据库驱动 | SQLite | `sql.js`（WASM） | 零编译依赖；代价是需手动 `persist()` |
| 出图模型档位 | Seedream 5.0 | 开发 light / 验收 pro | 一行替换，控制额度 |
| 前端路由 | 单页多态 | 视图状态切换 + hash 路由 | 用户端状态切换，管理端 hash |
| `gen_type` | 仅 `product_set` | v1.1 扩 `ai_image` / `image_edit`；v1.2 扩 `viral_remake` / `recolor` / `style_variants` | 每次扩展需**同步管理端标签映射** |
| 差异化入参 | 无约定 | v1.2 起统一进 `gen_params` JSON | 不再为每个功能加列，避免反复迁移 |

> ⚠️ `shot_type` 的不一致在 PRD 与 schema 之间客观存在，已在 T06 决策记录中固化。改动需**同步修改 PRD §6.3、schema.sql、T06 模板与管理端标签映射**四处，避免管理端筛选丢数据。
> ⚠️ `gen_type` 每新增一个取值，管理端生图记录的标签与筛选必须同步（T09/T10 的标签映射表是单点）。

## 9. 命名与格式约定

- 文件名：`T{两位序号}-{英文简述}.md`，全部小写、连字符分隔（如 `T21-async-jobs-and-task-center.md`）
- 文件**正文仍为中文**：一级标题格式为 `# T{序号} · {中文标题}`，链接文本用中文，仅文件名英文化
- 每个 ticket 固定十节：目标 / 背景与范围 / 前置依赖 / 任务清单 / 关键实现 / 涉及文件 / 验收标准 / 自测记录 / 风险与决策 / 遗留与后续
- 未启动的 ticket 第 8 节改为**验证计划（待执行）**，不伪造测试结果
- 状态取值：⬜ Todo ｜ 🟡 In Progress ｜ ✅ Done ｜ ⛔ Blocked
- "背景与范围"必须写**明确排除**，用于固化范围控制决策
- v1.1 / v1.2 ticket 头部标注**规格状态**，区分"PRD 已定义"与"规划待 PRD 升版"
