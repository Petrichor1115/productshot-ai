# T17 · AI 生图功能开通与意图路由

> 状态：⬜ Todo ｜ 优先级：P1 ｜ 阶段：v1.1 功能开通
> 依赖：T03、T06、T07 ｜ 来源：PRD §4.2 四大暂不开通功能（AI 生图排首位）
> 规格状态：v1.1 规划；PRD v2.1 仅规定"点击提示即将上线"，未定义具体行为

## 1. 目标

开通四大预留功能中的"AI 生图"：支持文生图与图片编辑两类意图，通过意图路由分流到不同模型档位，并为其余三功能（爆款复刻 / 商品换色 / 风格裂变）提供可复用的接入范式。

## 2. 背景与范围

**问题**：v1.0 五个入口中四个只弹 toast。AI 生图是最基础的一项，且与商品套图共享上传与结果展示链路，改造成本最低，适合作为首个开通项。

**在范围内**
- 意图识别：区分"从无到有生成"与"编辑已有图片"
- 文生图走 Seedream 文生图；图片编辑走支持编辑的档位（PRD 提及 5.0 Flash 定位）
- `gen_type` 新增 `ai_image` 与 `image_edit`，管理端标签同步
- 复用会话、上传、结果展示与下载链路

**明确排除**
- 爆款复刻 / 商品换色 / 风格裂变三个功能 → 本 ticket 只铺范式，不开通
- 多轮对话式改图（"再亮一点"）→ v1.2
- 图层拆分、透明背景导出 → 悬空

## 3. 前置依赖

- T03（模型客户端）、T06（生成与记录）、T07（入口与 UI）

## 4. 任务清单

- [ ] 意图识别：基于用户输入是否带图 + 动词特征判定 generate / edit

## 5. 关键实现

```js
// 意图路由：按是否有图 + 指令特征分流
function routeIntent({ hasImage, text }) {
  if (!hasImage) return { genType: 'ai_image',  model: SEEDREAM_T2I };
  if (/调亮|调色|去掉|替换|背景/.test(text))
                  return { genType: 'image_edit', model: SEEDREAM_EDIT };
  return { genType: 'ai_image', model: SEEDREAM_I2I };
}
```

**成本考量**：编辑档位与生成档位单价不同，路由同时决定成本，需在管理端能按 `gen_type` 分别统计（为 T19 计费铺垫）。

## 7. 验收标准（AC）

1. 纯文字输入走文生图，产出图片且 `gen_type=ai_image`。
2. 带图 + "把背景换成白色"走编辑链路，`gen_type=image_edit`。
3. 编辑失败时降级为文生图并明确提示，不静默失败。
4. 管理端能按三种生图类型正确显示标签与筛选。
5. 其余三个功能入口仍为 toast，不受影响。
6. 生成耗时与额度消耗在管理端可区分统计。

## 9. 风险与决策

| 决策 | 原因 |
|------|------|
| 首期只开 AI 生图 | 与现有链路复用度最高，风险最低；其余三项需各自的产品定义 |
| 规则式意图识别而非模型判断 | 免一次模型调用，成本低、延迟小；准确率不足时再换 LLM |
| 编辑失败降级而非直接报错 | 保证用户总能拿到结果 |
