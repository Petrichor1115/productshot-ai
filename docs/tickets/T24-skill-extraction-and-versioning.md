# T24 · Skill 自然语言萃取与版本管理

> 状态：⬜ Todo ｜ 优先级：P2 ｜ 阶段：v1.2 能力扩展
> 依赖：T16、T03 ｜ 来源：T16 遗留项（自然语言创建 Skill、版本管理与回滚）· `作业要求.md` 提及"基于聊天绘画萃取创建 skill"
> 规格状态：v1.2 规划；PRD v2.1 未定义 Skill 生命周期

## 1. 目标

让用户用自然语言描述或直接从历史会话一键萃取出 Skill，并支持版本迭代、对比与回滚，使 Skill 从"一次性保存"变为可持续优化的资产。

## 2. 背景与范围

**问题**：T16 的"另存为 Skill"本质是把当前参数原样存一份，用户仍需自己命名与整理，也未解决"改坏了想回退"的问题。作业要求提到的"萃取"暗示了从对话中自动提炼的能力。

**在范围内**
- 自然语言创建：用户描述风格偏好 → LLM 提炼为结构化 Skill 配置 → 用户确认后保存
- 会话萃取：读取会话的 messages（T14）+ generations 提示词 → 提炼风格关键词与模板骨架
- 版本管理：`skill_versions` 表，每次修改生成新版本
- 版本对比与一键回滚
- 生成时可选指定版本

**明确排除**
- Skill 市场 / 交易 / 跨用户分享 → v1.3
- Skill 自动效果评分与推荐 → 需评测体系，悬空
- 多 Skill 组合叠加 → 语义易冲突，悬空

## 3. 前置依赖

- T16（Skill 存储与隔离）、T14（聊天消息流水，萃取输入）、T03（模型客户端，用于提炼）

## 4. 任务清单

- [ ] 建 `skill_versions` 表：skill_id / version / config JSON / change_note / created_at
- [ ] 自然语言创建接口：输入描述 → LLM 输出 `{ name, styleKeywords, promptTpl }` → 前端确认卡
- [ ] 会话萃取接口：聚合该会话的补充信息、风格、历史 prompt → LLM 提炼 → 确认卡
- [ ] 确认卡必须允许编辑后再保存，不能"AI 说什么就是什么"
- [ ] 修改 Skill 时自动升版本并写 change_note
- [ ] 版本列表与差异对比（关键词与模板 diff）
- [ ] 回滚：以指定版本 config 生成新版本，而非物理删除历史
- [ ] 生成接口支持 `skillVersion` 入参，默认用最新版

## 5. 关键实现

```js
// 回滚 = 以历史 config 追加新版本，历史只增不减
function rollback(skillId, targetVersion) {
  const cfg = getVersion(skillId, targetVersion).config;
  insertVersion({ skillId, config: cfg, change_note: `回滚至 v${targetVersion}` });
}

// 萃取提示词：明确输出结构与约束，便于解析
const EXTRACT_PROMPT = `从以下会话内容中提炼该用户的稳定风格偏好，
输出 JSON：{ name, styleKeywords[], supplement, promptTpl }。
只提炼反复出现的偏好，忽略一次性要求。`;
```

**版本只增不减**：回滚不删历史版本，保证任何时刻都能回到任意历史点，也便于追溯"谁在什么时候改了什么"。

## 7. 验收标准（AC）

1. 用自然语言描述"我偏好日系清淡、柔光、浅木背景"能产出合理 Skill 配置。
2. 从历史会话萃取出的关键词与该会话实际风格一致（人工抽检 5 例）。
3. 确认卡可编辑，保存的是编辑后的内容。
4. 每次修改生成新版本号，历史版本仍可查看。
5. 回滚后可再次回滚回去，历史不丢失。
6. 生成时指定旧版本能生效，产物符合该版本配置。
7. LLM 返回非法 JSON 时有容错与重试，不崩溃。

## 9. 风险与决策

| 风险 | 应对 |
|------|------|
| LLM 提炼结果不稳定 | 走确认卡而非直接保存；保留一键改用手动创建 |
| 版本表无限增长 | 单 Skill 保留最近 20 个版本，超出归档旧版本（不删） |
| 萃取时会话内容过长 | 只取最近 N 轮 + 成功生成的 prompt，控制 token |
