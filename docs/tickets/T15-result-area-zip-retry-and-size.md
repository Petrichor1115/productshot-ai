# T15 · 结果区增强：ZIP 下载、单张重生成与尺寸扩展

> 状态：⬜ Todo ｜ 优先级：P1 ｜ 阶段：v1.1 用户端
> 依赖：T06、T08 ｜ 来源：T08 遗留项

## 1. 目标

补齐结果区三项能力：全部图片打包为 ZIP 下载、单张不满意可单独重新生成、输出尺寸从固定 1:1 扩展为多比例。

## 2. 背景与范围

**问题**：v1.0 下载为依次触发多文件下载（用户需逐个确认保存），单张不满意只能整组重生成（浪费额度与时间），尺寸仅支持 1:1。

**在范围内**
- `GET /api/download/zip?sessionId=N` 服务端打包
- 单张"重新生成"按钮，只重跑该 `shot_type`
- 尺寸比例扩展：1:1 / 3:4 / 16:9，回写 `image_size` 与 `api_size`
- 结果区操作按钮区重排布

**明确排除**
- 图片在线裁剪 / 构图调整 → 悬空
- 自定义分辨率输入 → 仅提供预设档位
- 批量跨会话打包 → v1.2

## 5. 关键实现

```js
// ZIP 流式打包，避免整包驻留内存
res.setHeader('Content-Type', 'application/zip');
res.setHeader('Content-Disposition', `attachment; filename="${encodeURIComponent(name)}.zip"`);
const archive = archiver('zip', { zlib: { level: 9 } });
archive.pipe(res);
rows.filter(r => r.status === 'success').forEach(r => archive.file(r.saved_path, { name: ... }));
await archive.finalize();
```

**重生成的记录策略（待决策）**：更新原记录（列表干净，但丢历史）vs 新增版本记录（可追溯，但列表膨胀）。当前倾向新增记录并标记 `retry_of`，需在实现前确认。

## 7. 验收标准（AC）

1. 点击"全部下载"只触发一次保存，得到含全部成功图片的 ZIP。
2. 失败图片不进入 ZIP，且不导致打包报错。
3. 单张重新生成后，仅该张变化，其余两张保持不变。
4. 选择 3:4 后出图比例确实为 3:4，且 `api_size` 正确透传。
5. ZIP 中文文件名在各浏览器下不乱码。
6. 空结果（全部失败）时下载按钮禁用或提示无可用图片。

## 9. 风险与决策

| 决策 | 原因 |
|------|------|
| 服务端打包而非前端 JSZip | 前端需先把图拉到内存，大图体验差；服务端流式更稳 |
| 尺寸只给预设档 | Seedream 对 size 有合法枚举，自由输入易报错 |
| 重生成记录策略 | 影响数据模型，实现前需与产品确认（见 §5） |
